# 코랩 세션 리포트 · AI 기반 UI/UX 디자인 시안 제작

**미션:** AI에 입력할 지시문(프롬프트)으로 화면을 만들고, 글자를 고친 뒤 화면을 연결한 시제품(프로토타입)을 완성한다.

## 1장. 개요

이번 코랩 세션은 조원들이 각자의 작업을 마무리한 뒤 만나 결과물과 작업 과정을 공유하고 질문하며 비교하는 시간이었다. 팀원은 나를 포함해 총 5명이며, 이 중 1명은 현장에 오지 못해 Discord로 참여했다.

나는 이미지 만들기부터 이미지 수정, 작업 기록, Figma 화면 연결과 코드로 옮기는 작업까지 결과물을 완성해 공유했다. 다른 조원들도 각자의 작업을 마무리한 뒤 결과물과 작업 과정을 공유했다. 노트북을 가져오지 않은 조원은 다른 팀원들의 작업을 살펴보고 질문하며 참여했다. 서로 Figma 사용법을 공유하고 작업 과정을 처음부터 끝까지 보여 주어, 팀원들이 이후 혼자서도 Figma를 사용할 수 있도록 했다.

## 3장. 지시와 구성 대조

### 3-1. 지시와 결과

| | 요청 내용 요약 | AI 생성 결과 | 요청하지 않았지만 추가된 내용 | 재요청 횟수 | AI 작업 중 이해하기 어려운 부분 |
|:-:|---|---|---|---|---|
| 1 | 추천 도예 수업과 카테고리가 있는 메인 화면 | 검색창, 추천 사진, 카테고리, 인기 목록과 탭 5개 | 검색·찜·마이페이지와 인기 카드 | 메인 1회 | 인기 수업 카드의 개수와 위치를 왜 그렇게 정했는지 알기 어려웠다. |
| 2 | 같은 색상을 쓰는 목록과 상세 화면, 사진과 글자 공간 분리 | 목록은 사진 3개와 정보 영역, 상세는 사진과 한글을 생성 | 목록의 선택 버튼과 아이콘이 늘었고 상세에 글자가 추가됨 | 화면당 0회. 마지막으로 글자를 넣을 때 수정 | 상세 화면에서 글자를 넣지 말라는 지시에도 문구가 생성된 이유를 확인하기 어려웠다. |

### 3-2. 수정 기록

| | 수정한 내용 | 수정한 이유 | 수정 후 달라진 점 |
|:-:|---|---|---|
| 1 | 만든 화면에서 필요한 사진을 잘라내고 한글·가격·일정을 HTML/CSS로 다시 입력했다. | 작은 한글과 숫자가 읽기 어려웠다. | 화면 정보를 읽을 수 있고 글자와 정보의 구성을 직접 관리할 수 있게 됐다. |
| 2 | 필요 없이 추가된 메뉴와 아이콘을 정리하고 화면을 연결했다. | 보여 주려는 주요 화면 이동에 집중할 필요가 있었다. | 메인 → 목록 → 상세 → 예약 미리보기의 흐름을 보여 줄 수 있게 됐다. |

### 3-3. 질문과 답변

세션에서는 노트북이 없는 조원도 다른 팀원의 작업을 보며 질문했고, Figma 사용법과 처음부터 끝까지의 작업 과정을 함께 확인했다. 다음은 공유한 내용을 질문과 답변으로 정리한 것이다.

| 질문 | 답변 |
|---|---|
| Figma에서 화면을 연결하는 작업은 어떻게 익혔는가? | 팀원끼리 사용법을 공유하고 처음부터 끝까지 작업 과정을 함께 보며 각자 사용할 수 있도록 익혔다. |
| 이미지로 화면 크기에 맞춰 바뀌는 페이지를 만드는 기능은 어디에 활용할 수 있는가? | 고객에게 보여 줄 시안이나 프로토타입을 빠르게 만드는 데 활용할 수 있다. |

### 5-1. 작업 방식 비교

|:-:|---|---|---|---|

| 2 | 화면 이미지 제작 | 메인·목록·상세와 예약 미리보기 화면을 정리했다. | 조원들도 완성한 화면 결과물을 공유했다. | 화면 구성과 제작 과정을 함께 살펴보며 다른 접근 방식을 확인할 수 있었다. |
| 3 | 작업 참여 방식 | 내 결과물과 작업 과정을 공유했다. | 노트북을 가져오지 않은 조원은 다른 팀원의 작업을 보며 질문했다. 한 명은 Discord로 참여했다. | 각자의 상황에 맞춰 결과물을 살펴보고 Figma 사용법을 공유할 수 있었다. |

| 공유 내용 | 인상적인 점 | 적용 방안 |

## 6장. 개선 계획

### 6-1. 회고

| 항목 | 내용 |
|---|---|
| 예상 외 발견 | Figma는 사용법이 쉽고 한눈에 이해하기 좋았다. 이미지로 화면 크기에 맞춰 바뀌는 페이지를 만드는 기능은 고객에게 보여 줄 시안 제작 시간을 줄일 가능성이 있다고 느꼈다. |
| 반복 작업의 불편 사항 | 이미지에서 읽기 어려운 글자와 필요 없는 부분을 정리하고 글자를 다시 입력하는 과정이 필요했다. |
| 다음에 AI에게 더 맡기고 싶은 작업 | ChatGPT로 화면 이미지를 만들고 Figma MCP를 활용해 화면 구성과 프로토타입 작업을 진행하는 방식을 시험해 보고 싶다. |

바이브 코딩을 활용하는 현재의 작업 방식에서는 Figma를 직접 클릭하며 계속 사용하지는 않을 것 같다. 현업에서 Figma 사용이 줄어들고 있다는 개인적인 인식도 있다. 다만 고객에게 초기 예시를 빠르게 보여 주는 용도로는 가치가 있다고 생각한다. Figma MCP를 쓰면 실제 웹페이지 구현에 드는 토큰 비용도 줄어들 수 있다고 예상하지만, 아직 비교 측정한 결과는 아니다.

### 6-2. 수정 계획

| | 수정 사항 |
|:-:|---|
| 1 | 제출 전에 최종 UI의 글자와 이미지를 점검한다. Figma 프로토타입은 조원 전원의 접속을 확인했다. |
| 2 | ChatGPT 이미지 생성과 Figma에서 화면 크기에 맞춰 바뀌는 페이지를 만드는 기능 및 Figma MCP를 연결하는 흐름을 시험하고, 걸린 시간과 토큰 비용을 실제 구현 방식과 비교한다. |

### 6-3. 유지 결정

| 유지 항목 | 유지 사유 |
|---|---|
| 메인 → 목록 → 상세 → 예약 미리보기 흐름 | 수업을 발견하고 비교한 뒤 예약 내용을 확인하는 서비스 이용 순서를 설명하기 쉽다. |
| 사진을 따로 잘라내고 글자를 다시 입력하는 방식 | 생성 이미지의 한글과 숫자를 읽기 쉽게 수정하고 같은 방식으로 관리할 수 있다. |

### 6-4. 미해결 사항

| 미해결 항목 | 어려움을 겪었거나 확인할 부분 |
|---|---|
| Figma MCP를 활용한 제작 흐름과 비용 | 실제 작업에서 걸리는 시간과 토큰 사용량을 아직 비교하지 않았다. |
