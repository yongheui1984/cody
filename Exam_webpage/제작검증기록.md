  - 이 페이지는 처음 방문한 사람이 조건을 입력하고 결과를 읽는 서비스라서 첫인상과 읽기 편한 화면이 중요하다고 판단했고, 이 점에서 더 완성도 있게 느껴진 AI A를 최종 결과물로 정했다.

## 수정 기록

### 수정 기록 1
- 발견한 문제: 모바일에서 추천 결과가 최대 53개까지 한 번에 나와 보기 힘들다. 비교 보관함은 시험이 세로로 하나씩만 보여 항목끼리 나란히 비교할 수 없다.
- AI에게 전달한 요청: "모바일 버전으로 살펴보았을때 기능은 다 잘 동작하고 화면 짤림 같은 문제도 없지만, 너무 많은 숫자의 자격증/시험 매칭 결과가 나오다 보니, 보기가 힘들었고, 특히 담기후 비교 기능은 작동하지만 모바일버전에서는 세로로 한번에 하나의 자격증/시험 내용만 보여지게 되어 원래 기능 의도인 비교를 하기는 매우 힘들었다."
- 이어서 전달한 구체적 요청: "'지금 도전 가능', '조건부', '지금은 불가' 제목 부분에 토글이 있어서 이 토글 버튼을 누르면 해당하는 내용이 나오도록 해야한다. 하단 부분에 '전체 시험 둘러보기'도 모바일 버전에서는 토글 버튼이 있고, 그걸 누르면 내용이 나오도록 수정되어야 한다. '비교 보관함'은 모바일에서 4개의 시험 내용을 비교하기에는 화면이 너무 작다. 이건 어떻게 하면 좋을지 너가 알아서 아이디어를 내서 고쳐봐. 원본 'claude.html'은 건들지 말고, 'claude_v1.html'을 생성해라."
- 수정 후 테스트 결과: 수정본은 `claude_v1.html`이고 원본 `claude.html`은 바꾸지 않았다. 폭 390px 화면(AI가 만든 모바일 크기)에서 만 27세, 대한민국, 학사, 경력 2년(은행·금융), 하루 2시간, 6개월로 `추천 보기`를 눌렀다. 지금 도전 가능 32개, 조건부 21개, 지금은 불가 0개(합계 53개)가 나왔고, 세 묶음은 모두 제목과 개수만 보이는 접힌 상태로 시작했다. 제목을 누르자 해당 묶음의 카드 32개가 열렸다. 위쪽 요약 칩을 누르면 해당 묶음이 열리는 것도 동작했다. 전체 시험 둘러보기는 처음에 접혀 있고(높이 0) 버튼을 누르면 열렸으며(높이 880px), 안쪽 난이도 구역 6개는 접힌 상태로 열렸다. 시험 4개를 담아 비교 보관함을 보니 항목 12개가 항목별로 접히고 펼쳐지는 칸으로 나왔고, 난이도·합격률·학습시간·응시료 4개 칸이 처음부터 열려 있었다. 칸 안에서 시험 4개가 위아래로 쌓여 로고, 이름, 값을 같이 볼 수 있었다. 학습시간 최단, 응시료 최저 표시가 붙었다. 담기 버튼과 하단 "비교 보관함 3/4" 바, 상단 개수 표시가 함께 바뀌었다. 폭 1300px 데스크탑에서는 묶음이 모두 열린 상태로 시작했고 비교는 4열 표로 나왔다. 폭 390px에서 가로 넘침은 없었고 콘솔 오류도 없었다. 실제 휴대폰과 Safari에서의 확인은 아직 하지 않았다.
- 수정 이유: 모바일에서 결과가 53개까지 이어지면 훑어보기 어려워서, 사용자가 필요한 묶음만 열어 보게 했다. 비교는 시험을 가로로 4개 놓으면 칸이 너무 좁고 세로로 하나씩 보여 주면 비교가 안 되므로, 항목 하나를 기준으로 시험 4개를 위아래로 쌓아 값을 바로 대조하게 했다.

### 수정 기록 2
- 발견한 문제: 디자인이 협업 수준의 최종 결과물에 못 미친다. 이미지와 움직임이 없고, 시험이나 주관기관을 알아볼 로고가 없다.
- AI에게 전달한 요청: "디자인이 너무 별로다. 이건 협업 수준의 최종결제물 수준이 아니다. 데모 수준도 안된다. 이미지와 애니메이션 효과를 넣고, 각 시험별로 시험에 해당하는 시험로고나 시험주관사의 로고를 넣어라. 너가 만들어서 넣는게 아니라, 실제로 웹에서 찾아서 넣어라."
- 수정 후 테스트 결과: 주관기관 34곳의 로고를 각 기관 공식 사이트(일부는 Wikimedia Commons에 올라온 공식 로고)에서 내려받아 시험 53개에 연결했다. 추천 카드, 둘러보기 카드, 응시요건 표, 비교표, 상세 창 머리, 비교 보관함 바에 로고가 나왔다. 여러 기관이 함께 주관하는 시험은 로고를 여러 개 보여 준다(예: Series 63은 NASAA와 FINRA, 은행 공채 필기는 5개 은행). 한국신용정보협회(신용관리사)는 공식 로고를 찾지 못해 기관명 글자 칩으로 표시했다. 금융감독원은 글자가 없는 상징 이미지만 구했다. 머리말에는 여의도 금융가 사진(Wikimedia Commons, CC0)을 넣었고, 수치 카운트업, 로고 띠 흐름, 스크롤 등장, 카드 호버, 토글 열림 효과를 확인했다. 시스템의 움직임 줄이기 설정이 켜지면 움직임이 꺼지도록 했다. 화면은 다크 모드에서만 눈으로 확인했고 라이트 모드는 보지 못했다.
- 수정 이유: 사용자가 정한 기준(협업 수준의 완성도, 실제 로고, 이미지와 움직임)에 맞추기 위해서다. 로고는 직접 그리지 않고 실제 파일을 받아 쓰라는 요청에 따라 공식 출처의 파일만 사용했다.

### 수정 기록 3
- 발견한 문제: 시험 상세 창의 공식 사이트와 출처 링크 중 깨진 것이 꽤 있다.
- AI에게 전달한 요청: "내용중에 링크가 깨진것들이 꽤 있다. 이걸 조사해서 너가 직접 확인해보고 죽은 링크는 아예 삭제해라."
- 수정 후 테스트 결과: `claude_v1.html`에 들어 있는 서로 다른 주소 212개(시험 53개의 공식 사이트와 출처 주소 211개, 본문 속 주소 1개)를 모두 열어 응답 코드, 이동한 주소, 페이지 제목과 내용을 확인했다. 정상 200으로 응답한 것이 대부분이었고, 다음 6개가 문제였다. (1) `www.insure.or.kr`은 도메인 자체가 없다(변액보험판매관리사의 공식 사이트와 출처). (2) `www.fpsbkorea.org` 주소 2개는 서버에 연결되지 않고 Chrome에서도 오류 페이지가 나온다(AFPK의 출처 2개). (3) 삼일회계법인 공지 주소(`board_no=443`)는 404이다(재경관리사의 출처). (4) 한국금융연수원 `Qual.do?cmd=scheduleView`는 화면 없이 `{}`만 나온다(자산관리사, 신용분석사, 외환전문역 Ⅰ·Ⅱ종, 여신심사역의 출처 5개). (5) 국제공인내부감사사(CIA)의 본문에 적힌 IIA 합격률 안내 주소는 합격률 표가 없는 자격 허브 첫 화면으로 넘어간다. (6) `www.kcia.or.kr`은 열리지만 한국신용정보협회가 아니라 대한화장품협회 사이트다(신용관리사의 공식 사이트와 출처에 잘못 연결). 이 주소들을 `claude_v1.html`에서 삭제했다. 지운 것은 출처 항목 10개, 공식 사이트 주소 2개(변액보험판매관리사, 신용관리사), 본문 속 주소 1개(문장은 두고 주소만 뺐다)이다. 삭제 뒤 상세 창을 열어 보니 오류 없이 열렸고, 남은 링크 중 삭제한 주소는 없었다. 변액보험판매관리사는 출처가 그 한 개뿐이어서 이제 출처 링크가 없다. ACAMS 6개와 Prometric 1개는 서버가 자동 접속을 막아 403이 나왔지만 Chrome에서는 정상으로 열려 남겼다. FRED 환율 주소도 프로그램 접속은 실패했으나 Chrome에서 정상이어서 남겼다. 다른 주소로 안내되지만 화면이 있는 링크(CAIA 회원 요건, ACCA 수수료, 한국세무사회 등)도 남겼다. 원본 `claude.html`은 바꾸지 않았다. 한계: 서버 응답, 이동 주소, 제목과 짧은 본문의 오류 문구로 판정했으므로, 정상 화면처럼 보이지만 내용이 바뀐 페이지는 가려내지 못했다.
- 수정 이유: 열리지 않거나 엉뚱한 곳으로 가는 링크는 사용자가 출처를 확인할 수 없게 만들고 자료의 신뢰를 떨어뜨리기 때문에, 직접 열어 보고 확실히 죽은 것만 지웠다. 접속을 막았을 뿐 사람에게는 열리는 링크까지 지우면 멀쩡한 출처를 잃게 되므로 남겼다.

### 수정 기록 4
- 발견한 문제: 모바일에서 화면이 짤리는 곳이 많다. 토글 버튼과 비교 보관함의 배치는 좋다.
- AI에게 전달한 요청: "수정사항들이 적용이 잘되서 모바일 버전에서 토글 버튼과 비교함에서의 배치도 아주 좋다. 하지만, 모바일버전에서 전체적으로 화면이 짤리는 곳이 많다. 이건 너가 직접 열어서 확인하고 스크린샷 찍어서 확인해라. 나는 크롬에서 개발자모드로 아이폰16pro max 모드로 확인했다." 원본 `claude_v1.html`은 두고 `claude_v2.html`로 저장하라고 했다.
- 수정 후 테스트 결과: `claude_v1.html`을 `claude_v2.html`로 복사한 뒤 고쳤다. 아이폰 16 Pro Max의 화면 폭 440px과 같은 폭의 틀 안에 `claude_v2.html`을 열어 눈으로 보고 스크린샷을 찍었다. 만 27세, 대한민국, 학사, 경력 2년(은행·금융), 하루 2시간, 6개월로 `추천 보기`를 누르고 시험 4개를 담은 상태에서 추천 결과, 전체 시험 둘러보기 세 탭, 비교 보관함, 하단 바를 차례로 확인했다. 짤린 곳은 네 군데였다. (1) 시험을 담으면 화면 아래에 뜨는 비교 보관함 바가 440px에서 깨졌다. 기관 로고가 "비교 보관함 4/4" 글자와 `비교 보기`, `비우기` 버튼 위에 겹치고 `비우기`가 가려졌다. 로고를 숨기는 기준이 420px이어서 440px에서는 숨겨지지 않았기 때문이다. 기준을 719px로 올려 모바일에서는 로고 없이 글자와 버튼만 보이게 했다. (2) 전체 시험 둘러보기의 `응시요건 비교` 탭 표는 폭이 1040px인데 화면은 387px이라 표 안에서만 가로·세로로 스크롤되었고, 첫 칸을 뺀 나머지 항목이 거의 보이지 않았다. 모바일에서는 표를 시험마다 한 장의 카드로 바꿨다. 위에 로고·시험명·`비교에 담기`·`상세` 버튼을 두고, 아래에 최소 나이, 학력, 경력, 국적 제한, 시험 언어, 응시료를 항목 이름과 함께 2열로 놓았다. 열 제목은 정렬 버튼으로 남겼다. 이 과정에서 은행 공채 필기처럼 로고가 5개인 시험은 카드가 737px로 넘쳤고, 로고가 줄바꿈되도록 고쳐 해결했다. 데스크톱 표는 그대로다. (3) 비교 보관함 위쪽에 담은 시험을 보여 주는 칸에서 긴 시험명이 "통일 증권법 대리인 시험(S…"처럼 잘렸다. 모바일에서는 이름이 줄바꿈되어 전체가 보인다. (4) 추천 결과 카드의 기관 이름이 모바일에서 한 줄로 잘려 "North American Securities Administrators Association…"으로 끝났다. 모바일에서도 전체 문장이 보이게 했다. 고친 뒤 폭 440px에서 가로 넘침이 없는지 화면의 모든 요소를 프로그램으로 검사했고(추천 결과 세 묶음, 둘러보기 세 탭의 모든 구역과 표, 비교 보관함, 하단 바, 머리말, 입력 칸), 시험 53개의 상세 창을 하나씩 열어 같은 검사를 했다. 모두 넘침이 없었고 글자가 말줄임으로 잘린 곳도 없었다. 만 17세 고졸 입력으로 `지금은 불가` 묶음이 나오는 경우도 확인했다. 폭 430, 414, 393, 390, 375px에서도 넘침이 없었다. 폭 360px에서는 둘러보기의 탭 막대(난이도별, 준비기간별, 응시요건 비교)가 9px 넘쳐 막대 안에서 가로로 스크롤되고, 320px에서도 같다. 이 부분은 고치지 않았다. 폭 1300px 데스크톱에서는 표가 그대로 표로 나오고 하단 바에 로고가 그대로 보였다. 원본 `claude_v1.html`과 `claude.html`은 바꾸지 않았다. 한계: 실제 아이폰이나 Safari, Chrome 개발자 도구의 기기 모드가 아니라, 데스크톱 Chrome 안에 폭 440px 틀을 만들어 확인했다. 기기 모드와 글꼴 크기, 주소창 높이가 조금 다를 수 있다.
- 수정 이유: 사용자가 쓰는 폰은 화면 폭이 440px인데, 이전 수정은 390px 기준으로 확인해서 420px 이하에만 적용한 규칙이 440px에서 빠져 있었다. 표는 폭이 넓어서 모바일에서 한 번에 읽히지 않으므로 항목별 카드로 바꾸어 가로 스크롤 없이 보게 했다.

### 수정 기록 5
- 발견한 문제: 수정 기록 4 이후에도 모바일에서 화면이 짤리고, 가로로 살짝 스크롤되며, 수정 이전보다 더 짤린다는 사용자 지적이 있었다.
- AI에게 전달한 요청: "현재도 모바일버전으로 했을때 짤린다. 횡기준으로 맞춰져야하는데 횡에서도 살짝 스크롤이 되게 지금 내용이 화면보다 크다. 지금은 수정 이전보다 더 짤린다."
- 수정 후 테스트 결과: 이 기록에서는 `claude_v2.html`을 고치지 않았다. 지적을 재현하려고 먼저 `body`의 `overflow-x:hidden`을 풀어 넘침이 가려지지 않게 한 뒤 다시 쟀다. 아이폰 16 Pro Max와 같은 폭 440px, 3배 화질의 모바일 에뮬레이션으로 `claude_v1.html`과 `claude_v2.html`을 다크·라이트 모드에서 열었다. 첫 화면, 추천 결과, 세 묶음 펼침, 시험 4개 담기, 둘러보기 세 탭, 시험 53개의 상세 창을 차례로 확인했다. 모든 단계에서 가로로 밀어도 스크롤 위치는 0이었고 화면 배율은 1이었으며, 폭 440px보다 넓게 나오는 요소는 로고 띠와 머리말 사진뿐이었는데 둘 다 바깥 상자에서 잘려 보이지 않는 부분이었다. 페이지, 둘러보기 세 탭, 비교 보관함, 상세 창 어디에도 안쪽 가로 스크롤 상자는 없었다. 접힌 기본 상태의 첫 화면부터 추천 결과까지도 폭 440px에서 눈으로 확인했고 잘린 곳이 없었다. 재현하지 못해 원인은 확정하지 못했고, 사용자에게 짤리는 화면의 스크린샷이나 구간을 물었다. 이후 사용자가 다시 확인했을 때는 짤리지 않고 잘 동작했다. 사용자가 처음 본 화면이 브라우저에 남은 이전 파일이었는지는 확인하지 못했다.
- 수정 이유: 수정 없이 재현이 되지 않는 지적에 근거 없이 코드를 바꾸면 이미 맞는 화면을 해칠 수 있어, 먼저 가로 넘침이 실제로 있는지 가려지지 않게 측정했다.

## 사용자 테스트
- 테스트 참여자와 요청한 작업: 이 페이지의 작성자(사용자) 본인. `claude.html`을 데스크탑 Safari와 Chrome에서 열어 보고, 추천된 시험을 담아 비교하고, 모바일 화면에서도 같은 작업을 해 보도록 했다.
- 사용자의 행동과 질문: 개발자 도구의 기기 모드로 휴대폰 화면을 보는 방법을 물었다.
- 받은 피드백: 데스크탑 Safari와 Chrome에서는 모두 잘 작동하고 담기 후 비교도 잘 구현되어 있다. 모바일에서는 기능이 모두 동작하고 화면 짤림도 없지만, 매칭 결과 숫자가 너무 많아 보기 힘들었다. 담기 후 비교는 한 번에 한 시험의 내용만 세로로 보여서 비교하기가 매우 힘들었다.
- 반영 내용과 결과: 모바일에서 결과가 너무 많고 비교가 어렵다는 피드백을 수정 기록 1에 반영해 `claude_v1.html`을 만들었다. 추천 결과의 세 묶음과 전체 시험 둘러보기를 제목을 눌러 여는 접이식으로 바꿨고, 비교 보관함은 항목 하나를 기준으로 시험 4개를 위아래로 쌓아 값을 바로 견주게 했다. 이후 사용자가 이 토글과 비교 보관함 배치가 아주 좋다고 확인했다. 다만 모바일에서 화면이 짤리는 곳이 남아 있다는 지적이 이어져, 수정 기록 4에서 하단 비교 바의 로고 겹침, 응시요건 비교 표, 긴 시험명과 기관명이 잘리는 곳을 고쳐 `claude_v2.html`로 저장했다. 수정 기록 5에서는 같은 지적이 다시 나왔지만 폭 440px 측정에서 가로 넘침을 재현하지 못했고, 사용자가 다시 확인했을 때는 짤림 없이 잘 동작했다. 데스크탑 Safari와 Chrome의 기능과 비교는 처음부터 문제가 없어 바꾸지 않았다. 실제 아이폰과 Safari 모바일에서의 확인은 아직 하지 않았다.
